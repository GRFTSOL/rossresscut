# 代码审查

## 一、正确性

检查：

- 是否符合需求。
- 是否存在明显逻辑错误。
- 是否处理错误路径。
- 是否处理边界条件。
- 是否存在资源泄漏。
- 是否存在任务取消问题。

---

# 二、架构

检查：

- Domain 是否依赖 UI。
- Media 是否依赖 UI。
- UI 是否直接操作 FFmpeg。
- 是否出现不必要的新 abstraction。
- 是否出现不必要的新 dependency。

---

# 三、egui

检查：

- UI update 是否执行阻塞操作。
- 是否每帧重复执行昂贵计算。
- 是否存在不必要 allocation。
- 是否正确管理 texture。
- 长任务是否在后台执行。

---

# 四、Rust

检查：

- `unwrap()` 是否合理。
- `expect()` 是否合理。
- 错误是否被吞掉。
- ownership 是否清晰。
- 生命周期是否被不必要复杂化。
- trait 是否真的有必要。

---

# 五、媒体

检查：

- Timestamp 是否正确。
- VFR 是否被错误假设成 CFR。
- PTS/DTS 是否混淆。
- stream index 是否正确。
- stream copy 是否真的没有重新编码。
- 输出失败是否被正确报告。

---

# 六、测试

确认：

- 新逻辑是否有测试。
- bug 是否有回归测试。
- 测试是否真的覆盖问题。
- 是否声称测试通过但实际没有运行。

---

# 七、最终判断

优先级：

```text
正确性
>
数据安全
>
架构边界
>
性能
>
代码简洁
>
代码美观
```

不要为了代码看起来漂亮而牺牲正确性。
