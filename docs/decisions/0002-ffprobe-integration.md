# 0002 FFprobe Integration and Media Time Model

- Status: Accepted
- Date: 2026-10-24
- Phase: Phase 1

## Context

Phase 1 needs to read reliable media information from typical containers and convert the results into a domain model decoupled from both the UI and the FFprobe JSON. Media time must use an integer representation; `f32` / `f64` seconds must not be the sole representation.

## Decision

### 1. Run FFprobe directly, without linking libav*

`std::process::Command` is used to launch `ffprobe` directly, passing each argument separately without going through a shell:

```text
ffprobe -v error -print_format json -show_format -show_streams -show_chapters <path>
```

FFI / `ffmpeg-next` / linking libav* are rejected: the project forbids `unsafe` and FFI, and the media-processing boundary has already been fixed as an external process.

### 2. JSON exists only inside the parsing boundary

`src/media/ffprobe/raw.rs` defines private serde structs, and `parse.rs` converts them into the domain model. `serde_json::Value` does not leave this boundary.

New dependencies:

- `serde` (derive): deserializing the FFprobe JSON.
- `serde_json`: JSON parsing and error context.

A hand-written JSON parser is rejected: the FFprobe output has many fields and optional ones, so hand-written parsing is more error-prone. Letting `serde_json::Value` propagate into the application layer is rejected: it would lose type constraints.

FFprobe fields such as `duration`, `size`, `bit_rate`, and `sample_rate` may actually appear as either strings or numbers, and `raw::Scalar` handles this uniformly inside the boundary.

### 3. The time model uses integer microseconds and rational time bases

- `Timestamp`: a signed `i64` in microseconds, negative values allowed (container start time can be negative).
- `Duration`: an unsigned `u64` in microseconds, negative values not allowed.
- `TimeBase`: a `u32/u32` rational number; `TimeBase::MICROSECONDS = 1/1_000_000` is the internal canonical base.
- Conversion formulas:
  - `seconds = ticks × numerator / denominator`
  - `micros = ticks × numerator × 1_000_000 / denominator`
- Conversions use `i128` intermediate values, rounding to the nearest value and away from zero on exact halves; overflow returns `None`.
- FFprobe's decimal-seconds strings are parsed with integer arithmetic, keeping at most 6 decimal places and rounding the 7th, without going through floating point.
- Chapters are converted using FFprobe's integer `start` / `end` and `time_base`, not the decimal `start_time` string.
- The UI display format is `HH:MM:SS.mmm`.

The `f64`-seconds model is rejected: it cannot stably express timestamp boundaries, PTS / time base conversions, and precise seeks.

### 4. Background probing, the UI does not block

`Application::open_media` starts a named thread and sends the result back via `mpsc`; the UI polls the non-blocking `Application::update` every frame. While probing, the UI repaints periodically via `request_repaint_after`.

Running FFprobe synchronously in the egui update is rejected, as is introducing an async runtime: Phase 1 has only one short task, and standard-library threads plus channels are sufficient.

When a new file is opened, the old task is replaced; the old result is discarded because the receiver is closed, and a `debug` log is recorded.

### 5. Stream classification and unknown streams

`MediaStream` is divided into `Video`, `Audio`, `Subtitle`, and `Other`. Unknown `codec_type` values are not discarded; their basic information is retained as `Other`.

`Disposition` models only the five flags the current UI needs; the remaining FFprobe flags are ignored and will be added when there is an actual use.

### 6. Test media is generated with FFmpeg lavfi

All fixtures in `tests/fixtures/` are generated by `generate.sh`, covering MP4, MKV, WMV, AVI, and MPEG-TS, and including multiple audio tracks, subtitles, chapters, and a non-zero start time. Integration tests invoke the real FFprobe and assert on domain model fields rather than relying on FFprobe's log wording.

## Consequences

- Running and testing depend on the system `ffprobe`; CI installs FFmpeg explicitly.
- Duration precision is based on the 6 decimal places of the FFprobe output, represented internally as microseconds.
- The domain model currently derives only `Serialize`; a validated `Deserialize` (in particular the non-zero constraint on `TimeBase`) will be added during the project's persistence phase.
- Phase 1 only reads `r_frame_rate` / `avg_frame_rate` and does not derive VFR timing from a fixed frame rate.
